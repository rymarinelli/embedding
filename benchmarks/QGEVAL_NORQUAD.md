# QGEval-style question-generation evaluation on NorQuAD

Evaluates **Claude Fable 5's question-generation ability** against NorQuAD's
own human-written questions as ground truth, emulating:

> Fu, Wei, Hu, Cai, Liu. *QGEval: Benchmarking Multi-dimensional Evaluation for
> Question Generation.* EMNLP 2024, pp. 11783–11803.

NorQuAD plays the SQuAD role in the original paper — it is a SQuAD-formatted
Norwegian news QA dataset, so its `(passage, answer, question)` triples map
directly onto QGEval's inputs.

## Why the questions had to be regenerated

The repo already contains `results/norquad_fable_questions.json` — 403
questions Fable generated from **passages alone**, under an explicit
"høynivå, ikke faktaspørsmål" instruction. Those are **not** usable here.

QGEval conditions generation on *passage + a target answer*, so the generated
question and the human reference aim at the **same answer**. That is what makes
reference-based metrics and the Answer Consistency dimension meaningful.
Scoring the high-level set against NorQuAD's short factoid references would
mostly re-measure a deliberate style difference, not question-generation
quality.

So a second set was generated — `results/qgeval_fable_questions.json` — using
the paper's neutral zero-shot QG instruction (their Table 9), translated to
Norwegian, with no steering toward question depth or style:

```
Lag et spørsmål basert på det oppgitte svaret og konteksten. Det genererte
spørsmålet må kunne besvares med det oppgitte svaret.
Svar: {answer}
Kontekst: {passage}
Spørsmål:
```

| Question set | Input | Purpose |
|---|---|---|
| `norquad_fable_questions.json` (403) | passage only, "make it høynivå" | Style contrast vs. NorQuAD — **not** a ground-truth comparison |
| `qgeval_fable_questions.json` (200) | passage **+ gold answer**, neutral prompt | **This evaluation** |

## Pipeline

```
python3 scripts/prepare_qgeval_sample.py 200        # -> data/qgeval_sample.json
python3 scripts/generate_questions_qgeval_fable.py  # -> results/qgeval_fable_questions.json
python3 scripts/score_qgeval_dimensions.py          # -> results/qgeval_judge_scores.json
python3 scripts/score_qgeval_metrics.py             # -> results/qgeval_metrics_*.csv
python3 scripts/report_qgeval.py                    # -> results/qgeval_*.png, *_scores.csv
```

200 passages, one question sampled per passage (seed 42), matching the paper's
200-passage scale.

## Judging protocol

`qgeval_dimensions.py` carries the seven dimensions and their 1–3 scoring
rubric **reproduced verbatim from the paper's Table 7** — three linguistic
(Fluency, Clarity, Conciseness) and four task-oriented (Relevance,
Consistency, Answerability, Answer Consistency).

Judge: **Claude Opus 5** via OpenRouter, G-EVAL style (one sentence of
reasoning before each score), which the paper found to be the best-correlating
automatic proxy for human annotation.

Two protocol choices follow the paper:

* All questions for a passage are judged in **one call**, as in the paper's
  annotation protocol ("all 15 questions generated by different models were
  presented simultaneously... helps annotators validate their judgments").
* **NorQuAD's own question is scored too.** The paper likewise scores the human
  reference as its own row (their Table 4), which is what makes "did the model
  beat the humans?" answerable at all.

One choice departs from the paper, to make the result more trustworthy:

* Systems are presented **blind and in randomized order** ("Question A" /
  "Question B"), so the judge cannot favour a system by label and position
  bias averages out. The mapping is stored per record for attribution.

## Results — per-dimension scores (n=200)

Scale 1–3, higher is better. W/T/L counts pairs where Fable wins / ties /
loses. Paired **Wilcoxon signed-rank** test (the scores are ordinal and paired
on the same items, so this replaces the paper's t-test).

| Dimension | Aspect | Fable | NorQuAD ref | Δ | W/T/L | p |
|---|---|---|---|---|---|---|
| Fluency | linguistic | 2.980 | 2.885 | +0.095 | 21/176/3 | <0.001 |
| **Clarity** | linguistic | **2.960** | **2.570** | **+0.390** | 76/120/4 | <0.001 |
| Conciseness | linguistic | 2.945 | 2.990 | **−0.045** | 2/187/11 | 0.013 |
| Relevance | task-oriented | 2.740 | 2.660 | +0.080 | 20/176/4 | 0.001 |
| Consistency | task-oriented | 2.990 | 2.855 | +0.135 | 25/174/1 | <0.001 |
| Answerability | task-oriented | 2.970 | 2.815 | +0.155 | 31/167/2 | <0.001 |
| Answer Consistency | task-oriented | 2.975 | 2.870 | +0.105 | 20/178/2 | 0.001 |
| **Avg.** | | **2.937** | **2.806** | **+0.131** | | |

**Fable outscores the human-written references on 6 of 7 dimensions.** This
mirrors the paper's own headline finding, where GPT-4-fewshot (2.929) edged
out the human Reference row (2.916).

**Clarity is the real story** (+0.390, 76 wins to 4; 96% perfect scores vs.
60%). The mechanism is visible in the data: NorQuAD's annotators wrote
questions that disambiguate only *given the passage in front of them*, while
Fable pins down specifics.

```
answer:    en gassdrevet bil
NorQuAD:   Hva slags bil kjørte av veien i Hurum?
Fable:     Hva slags bil kjørte av veien på Klokkarstua i Hurum?
```

That same added specificity is exactly why Fable **loses Conciseness** — the
one dimension where extra qualifiers are a cost rather than a benefit. The two
results are the same behaviour scored from opposite directions, which is
precisely the trade-off QGEval's multi-dimensional design exists to separate.

A second recurring pattern is answer-type matching:

```
answer:    hver fredag                    (a frequency, not a point in time)
NorQuAD:   Når kommer podcasten ... ut?   ("when")
Fable:     Hvor ofte kommer podkasten ... ut?  ("how often")
```

## Results — automatic metrics vs. judge scores

Reference-based metrics scoring Fable's question against NorQuAD's question:

| Metric | mean | median |
|---|---|---|
| BLEU-4 | 0.2318 | 0.1454 |
| ROUGE-L | 0.5129 | 0.5000 |
| METEOR | 0.4673 | 0.4556 |
| BERTScore | 0.8524 | 0.8526 |

Pearson correlation of each metric against each judge dimension:

| Metric | Flu. | Clar. | Conc. | Rel. | Cons. | Ans. | AnsC. |
|---|---|---|---|---|---|---|---|
| BLEU-4 | −0.022 | −0.021 | 0.134 | −0.057 | 0.026 | −0.001 | −0.014 |
| ROUGE-L | 0.006 | −0.049 | 0.136 | −0.012 | 0.004 | 0.031 | −0.009 |
| METEOR | −0.010 | 0.031 | 0.038 | 0.038 | 0.007 | 0.024 | −0.029 |
| BERTScore | 0.025 | −0.058 | 0.136 | −0.032 | −0.021 | −0.010 | −0.055 |

**Every |r| ≤ 0.14, most near zero — including BERTScore**, which is supposed
to capture semantics rather than surface overlap. This reproduces the paper's
central negative finding: n-gram and embedding overlap with a reference is a
poor proxy for question quality.

The reason is visible in the two result sets together. Fable's questions sit at
ROUGE-L 0.51 / BERTScore 0.85 against the references — moderately similar in
surface form — yet judged directly they are *better* than the references they
are being scored against. "Distance from the ground truth" is therefore
measuring the wrong thing: a question can only lose similarity points by
departing from the reference, including when it departs by being clearer.

The only column with any consistent signal is **Conciseness** (~0.135 for
BLEU-4/ROUGE-L/BERTScore), which makes sense — all three reward brevity and
penalise the extra qualifiers that also cost Fable its Conciseness score. It
is the one dimension where surface overlap and the rubric happen to agree.

Correlations here are flatter than the paper's (which reached ~0.4). Expected:
they compared 15 systems spanning a wide quality range, while this is a single
system, so there is far less quality spread for a metric to track.

## Further validation (`scripts/qgeval_deep_analysis.py`)

Five checks beyond the headline numbers, all from the existing artifacts.
Outputs land in `results/qgeval_analysis/`.

**Blinding held.** Splitting Fable's own scores by which slot it was presented
in tests whether presentation order leaked into the judging: **0 of 7
dimensions** show a slot effect (Mann-Whitney, all p ≥ 0.10). Fable drew slot A
103 times and B 97 times and scored the same either way.

**Effect sizes.** All seven 95% bootstrap CIs (10 000 resamples) exclude zero,
with rank-biserial 0.67–0.92. But every result rests on **13–80 non-tied pairs
of 200** — the rest tie at 3/3. Real, and small outside Clarity.

**Score distributions.** Clarity is the only dimension where either system
leaves the ceiling: 40% of NorQuAD's questions score below 3, against 4% of
Fable's. Score-1 ratings across all dimensions: Fable 3, NorQuAD 18 (of 1 400).

**The dimensions are not redundant.** Inter-dimension correlations run
−0.06–0.72 against the paper's 0.04–0.67, so the rubric transfers rather than
collapsing into one axis. Answerability↔Answer Consistency is tightest (0.72);
**Conciseness correlates ≈0.00 with all six others** — it measures something
genuinely separate, and it is the one dimension Fable loses.

**The Clarity/Conciseness trade-off is measurable, not just anecdotal.**
Correlating the extra words Fable uses against each score difference:

| | r | p |
|---|---|---|
| Clarity | **+0.259** | 0.0002 |
| Conciseness | **−0.441** | 6.2 × 10⁻¹¹ |

Same variable, opposite signs. Fable averages 10.1 words per question against
NorQuAD's 7.7 and is longer in 70% of pairs — but when it *loses* a Conciseness
point it has added **+7.7 words**, versus **+2.2** when it ties. It is not
verbose in general; it is penalised on the minority of questions where it
front-loads context.

## Reproducing the reported numbers

`scripts/qgeval_validate_results.py` re-derives every figure reported here
straight from `results/qgeval_judge_scores.json` — means, deltas, win/tie/loss
counts, p-values, perfect-score rates, metric means, and each quoted example's
scores — plus integrity checks that the gold answers still match the sample and
that both presentation slots were used.

It reads the raw judge output rather than the summary CSVs, so a bug in the
reporting layer cannot validate itself. 39 checks, currently all passing.

```
python3 scripts/qgeval_validate_results.py   # 39 checks
python3 scripts/qgeval_deep_analysis.py      # -> results/qgeval_analysis/*.csv
```

## Caveats

* **The judge and the generator are from the same family.** Claude Opus 5
  judging Claude Fable 5 cannot rule out self-preference, and none of the
  validation above tests for it — the blinding check only rules out *position*
  bias. This is the single biggest open question here, and only a judge from a
  different model family (Gemini, GPT, Qwen) settles it.
* **Single LLM judge, not three humans.** The paper's own data shows
  GPT-4+G-EVAL reaching only r≈0.36 with human annotators. These are an
  automated proxy, not human ground truth. A second judge plus a
  Krippendorff's α agreement analysis (as the paper reports for its
  annotators) is the honest next step before citing these numbers — and it
  doubles as the self-preference test above.
* **Ceiling effects.** Most pairs tie at 3/3 (e.g. 176/200 on Fluency), so the
  Wilcoxon p-values rest on a small number of discordant pairs. The results are
  statistically significant but the effect sizes are small outside Clarity.
* **METEOR is weakened.** There is no Norwegian WordNet, so METEOR degrades to
  exact/stem alignment rather than its full synonym-aware form. Still a valid
  overlap metric, but not equivalent to its English behaviour.
* **Reference quality is not a constant.** NorQuAD's questions were written by
  annotators who could see the passage, for a *retrieval/QA* dataset — they
  were never optimised for standalone clarity. Scoring them on a QG rubric is
  informative but slightly off-label.
