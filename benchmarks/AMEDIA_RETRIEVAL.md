# Amedia higher-level-question retrieval benchmark

Tests whether an embedding model can retrieve the correct source article for
a **higher-level** (Hvorfor/Hvordan/Hvilke...) comprehension question, as
opposed to NorQuAD's short factoid questions. Each of the 100 questions in
`results/amedia_fable_questions.json` (generated by Claude Fable 5, see
`generate_questions_amedia_fable.py`) has exactly **one** gold article among
the same 100 — a 1-to-1 corpus, much smaller and more saturated than
NorQuAD's 403-passage/2,398-query set.

## Pipeline

```
python3 scripts/build_amedia_corpus.py <source_jsonl>   # -> data/amedia_corpus.jsonl, data/amedia_queries.jsonl (gitignored)
python3 scripts/amedia_retrieval_benchmark.py [model_id ...]  # -> results/amedia_retrieval_results.csv
```

`amedia_retrieval_benchmark.py` reuses `retrieval_benchmark.py`'s `evaluate()`
function unchanged — same metrics (Recall@1/5/10, MRR@10, nDCG@10), same
model-loading logic (including the `MeanPoolingEncoder` for raw encoders and
the reduced batch size for Qwen3-based models), just pointed at this corpus.

**Amedia article text never leaves this machine.** `data/amedia_corpus.jsonl`
and `data/amedia_queries.jsonl` contain full (paywalled, proprietary) article
text and are gitignored. Only the metrics CSV — no article content — is
committed.

## Results (100 passages / 100 queries)

| model | recall@1 | recall@5 | recall@10 | mrr@10 | ndcg@10 |
|---|---|---|---|---|---|
| `intfloat/multilingual-e5-large` | **1.00** | 1.00 | 1.00 | **1.00** | **1.00** |
| `NbAiLab/nb-sbert-base` | 0.94 | 1.00 | 1.00 | 0.967 | 0.975 |

`multilingual-e5-large` retrieves the correct article at rank 1 for **all
100** questions. `nb-sbert-base` misses rank-1 on 6/100 but recovers every
one of them by rank 5 (checked directly: all 6 are near-misses — rank 2 or 3
— against a thematically adjacent article, e.g. a question about a hospital
director's reasoning on emergency-surgery closure narrowly outranked by
another healthcare-policy article; not a confused/unrelated retrieval).

**Why both models score much higher here than on NorQuAD's news corpus**
(nDCG@10 there was 0.83 / 0.60 respectively): this corpus is a fifth the
size (100 vs. 403 passages) and, by construction, every question was
generated specifically to have a unique, unambiguous source article
(Fable was explicitly prompted for this — see `generate_questions_amedia_fable.py`
and Rubrikk B in `amedia_rubrikker.md`). A saturated 1-to-1 corpus with
deliberately unique questions is a much easier retrieval task than a shared
403-passage pool where many different questions target overlapping content.
This isolates one specific question — *"can embeddings retrieve based on
higher-level thematic content, not just keyword overlap?"* — cleanly, but
it is not a like-for-like difficulty comparison with the NorQuAD numbers.

To run more models (e.g. the full NorQuAD retrieval roster), reuse the same
`MODELS` list from `retrieval_benchmark.py` — no code changes needed, just:
```
python3 scripts/amedia_retrieval_benchmark.py
```
